# REWIND RAMPAGE
## 第三幕：ERASE — 擦除
### 完整剧情演出脚本 v1.0

**游戏时长：** 90 秒，倒计时 `01:30 → 00:00`  
**开场衔接：** 第二幕身份验证及档案故障演出结束后  
**结尾演出：** 约 10–12 秒  
**场景：** 时间档案空间，延续原有 2D 电子网格竞技场  
**美术风格：** 深色电子网格、青色玩家、红色与紫红色时间残影、CRT 磁带故障效果  
**叙事方式：** 系统文本、环境变化、角色行为、HUD 和时间异常特效  
**背景音乐：** 不在本文档中规定

# 一、剧情背景

第二幕结束后，系统成功删除了玩家刚刚生成的录像幻影。

但随后进行的身份验证表明，当前玩家同样是由旧磁带记录重建出的复制体。

系统试图清理重复记录，却发现磁带擦除磁头已经失效。

大量本应被覆盖、删除的旧时间记录仍然保存在档案中。这些记录曾经生成过许多个体，而部分个体已经脱离固定录像的控制，获得了独立行动的能力。

系统无法恢复正常的记录状态，于是启动最后的时间档案清除程序。

**该程序将在 90 秒后执行最终清除。**

玩家与旧复制体同时被困在档案空间中。

这些旧复制体拥有与玩家相同的倒带能力，并会主动攻击玩家。

玩家需要在清除程序完成前摧毁时间核心，同时坚持到档案运行周期结束。

这里需要区分两种故障：

- **磁带擦除磁头损坏：** 旧磁带上的记录无法彻底清除，因此保留了大量时间残留。
- **时间档案清除程序：** 系统试图直接清除已经重建的个体，而不是单纯擦除磁带内容。

时间核心负责维持档案空间和清除程序。摧毁核心能够终止清除命令，但当前运行周期必须结束后，档案空间才能解除封锁。

# 二、开场：ARCHIVE PURGE

## 第三幕正式开始前

**演出时长：** 约 2–3 秒  
**倒计时：** `01:30`，暂不减少

本段直接承接第二幕结束时的档案暴露演出。

玩家已经知道自己也是复制品。

周围出现了多个与玩家相同的轮廓。

### 画面演出

1. 原本扩展的档案网格逐渐稳定。
2. 远处可以看到若干静止的复制体轮廓。
3. 竞技场外围的电子边框开始转为紫红色。
4. HUD 中的 `PLAY` 状态完全消失。
5. 磁带系统状态切换至 `ERASE`。
6. 屏幕中央出现最后一次系统检查结果。

### 屏幕文本

`> ARCHIVE ACCESS GRANTED.`

`> RESIDUAL INSTANCES DETECTED.`

`> ORIGINAL RECORD UNAVAILABLE.`

短暂停顿。

`> INITIATING EMERGENCY PURGE.`

随后出现：

**`ALL INSTANCES MARKED FOR ERASURE.`**

这里的 `ALL INSTANCES` 也包括玩家。

### 复制体苏醒

画面中，一个旧复制体首先开始移动。

随后另一个复制体短暂倒退，留下紫红色残影。

两个复制体转向玩家的位置。

它们的动作不使用第一、二幕的实际录像，而是在第三幕开始时由独立 AI 控制。

### 屏幕文字

`> ARCHIVE INSTANCES ACTIVE.`

`> PURGE CYCLE: 90 SECONDS.`

倒计时显示：

**01:30**

随后：

**`SURVIVE THE PURGE.`**

玩家恢复控制。

第三幕正式开始。

# 三、第一阶段：AWAKENING — 档案苏醒

## 剩余时间 01:30 → 01:00

**经过时间：** 0–30 秒  
**场上 Echo 目标数量：** 2

### 游戏过程

初始生成两个能够独立行动的 Echo。

Echo 使用与玩家相同的几何角色模型，但轮廓呈紫红色，便于区别于青色玩家。

每个 Echo 使用自己的随机移动逻辑，不依赖历史录像。

Echo 能够在移动过程中记录或生成自己的攻击路径，并在随机时机发动倒带攻击。

与玩家类似，Echo 倒带时会沿轨迹高速移动，并对路径上的玩家产生伤害判定。

### 01:25 — 第一次敌方倒带

首次有 Echo 准备发动倒带时，触发一次剧情提示。

### 画面演出

- 该 Echo 周围出现紫红色轮廓。
- 它的预定倒带路径开始闪烁。
- 轨迹逐渐由普通状态转为危险状态。
- 短暂预警结束后，Echo 沿轨迹发动倒带。

### 屏幕文本

`HOSTILE REWIND DETECTED.`

随后：

`TEMPORAL ABILITY CONFIRMED.`

该提示由首次敌方倒带事件触发，不强制敌人在 01:25 准确发动攻击。

### 剧情含义

玩家第一次真正面对拥有同等倒带能力的敌人。

第二幕的幻影只是重播玩家过去的行为，而这些 Echo 能够根据自己的状态行动。

### 01:15 — 独立实例确认

系统开始分析正在活动的复制体。

HUD 显示：

`> MULTIPLE ACTIVE INSTANCES.`

`> PLAYBACK CONTROL: OFFLINE.`

`> AUTONOMOUS BEHAVIOR DETECTED.`

### 画面表现

可以让场景中远处的静止复制体偶尔出现轻微运动或姿态变化。

这些背景轮廓不参与战斗，也不计入实际敌人数量。

真正参与战斗的 Echo 由现有生成系统管理。

### 01:05 — 系统稳定性下降

竞技场外围短暂闪过信号故障。

系统显示：

`ARCHIVE STABILITY DECREASING.`

紧接着：

`PURGE PRIORITY INCREASED.`

# 四、第二阶段：INTERFERENCE — 时间干涉

## 剩余时间 01:00 → 00:30

**经过时间：** 30–60 秒  
**场上 Echo 目标数量：** 3

### 01:00 — 第二阶段开始

当倒计时首次到达 `01:00` 时：

- Echo 目标数量提高至 3。
- 敌人倒带攻击的随机间隔缩短。
- 竞技场外围出现更多档案故障效果。
- HUD 的清除状态提示加强。

### 屏幕文字

`> PURGE PHASE 02.`

`> INCREASING INTERFERENCE.`

### 游戏过程

不同 Echo 各自选择移动方向和攻击时机。

它们的倒带轨迹可能互相交错。

玩家需要同时判断多个 Echo 的运动与危险轨迹，利用自己的倒带和轨迹交叉爆炸进行反击。

敌人的倒带攻击必须拥有明确的视觉预警。

随机性只能决定攻击何时发生、轨迹如何生成，不能在攻击过程中无预警地改变已经公布的危险路径。

### 00:50 — 档案异常

HUD 短暂显示：

`> RECORDING CONFLICT DETECTED.`

`> MULTIPLE OPERATORS ACTIVE.`

随后：

`> NO VALID ORIGINAL FOUND.`

### 画面演出

屏幕边框出现一次水平错位。

玩家和 Echo 的轮廓短暂出现录像式重影。

重影效果不能影响真实坐标、运动轨迹或伤害判定。

### 00:45 — 复制体状态检查

系统尝试辨认当前活动个体之间的差异。

显示：

`COMPARING INSTANCE SIGNATURES...`

短暂停顿。

`IDENTITY MATCH: 100%.`

随后：

`ORIGINAL STATUS: UNKNOWN.`

### 剧情含义

系统无法在玩家与其他 Echo 之间找到可以用于确定原版身份的区别。

玩家已经知道自己是复制体，但这一段进一步表明：

**对系统而言，玩家和周围的敌人都只是相同身份的多个实例。**

### 00:35 — 最终清除准备

竞技场边框开始出现持续性的红色警示灯。

系统显示：

`PREPARING FINAL ERASURE.`

随后：

`CORE ACCESS UNLOCKING...`

此时只进行演出，不提前生成时间核心。

### 画面效果

竞技场中心或预设的核心生成位置出现短暂的扫描框。

该位置的网格线逐渐变亮，提示即将发生变化。

# 五、第三阶段：SYSTEM COLLAPSE — 系统崩溃

## 剩余时间 00:30 → 00:00

**经过时间：** 60–90 秒  
**场上 Echo 目标数量：** 4

这是第三幕最终战斗阶段。

### 00:30 — 时间核心出现

倒计时达到 `00:30` 时：

1. 场景外围亮起红色警告。
2. 竞技场中央或预设位置的网格开始扭曲。
3. 时间核心从网格中逐渐实体化。
4. HUD 出现新的目标提示。
5. Echo 目标数量提高至 4。
6. 敌人的倒带攻击频率提升至本幕最高阶段。

### 屏幕文字

`> FINAL PURGE SEQUENCE ACTIVE.`

`> TEMPORAL CORE EXPOSED.`

随后：

**`DESTROY THE CORE.`**

### 时间核心视觉表现

时间核心建议使用与玩家、Echo 不同的几何图案。

可以使用三个相互嵌套的发光方形或圆环，围绕一个明亮的红色中心旋转。

核心外围存在三层清晰的结构，对应三次有效攻击。

每次受到攻击时，其中一层熄灭或破碎。

**不需要新增复杂的 3D 模型。**

整个核心可以完全由 2D 图形、简单旋转与发光特效构成。

### 时间核心规则

- 初始耐久为 3。
- 玩家可以使用已有倒带冲刺或轨迹交叉爆炸攻击核心。
- 每次有效攻击降低 1 点耐久。
- 同一次攻击事件不能重复造成多次核心伤害。
- 核心不受 Echo 攻击影响。
- 核心耐久归零后进入摧毁状态。

### 00:25 — 核心状态确认

如果核心尚未被摧毁：

`CORE INTEGRITY: CRITICAL.`

随后：

`ERASURE IMMINENT.`

### 游戏过程

Echo 继续随机移动和发动倒带攻击。

玩家需要在多个 Echo 的危险轨迹之间寻找机会，对核心完成三次有效攻击。

玩家可以优先攻击 Echo，也可以尝试直接攻击核心。

不要求玩家先击败指定数量的 Echo 才能攻击核心。

# 六、关键事件：TEMPORAL CORE DESTROYED

## 触发条件：时间核心耐久归零

此事件可能发生在剩余 `00:30–00:00` 之间的任意时刻。

**核心摧毁不会提前结束第三幕。**

### 核心受到最后一次攻击

当核心耐久降低至 0：

1. 核心停止旋转。
2. 核心外侧结构向外破碎。
3. 一道短暂的白色冲击波向竞技场边缘扩散。
4. 所有 Echo 暂时进入短暂硬直或停顿。
5. HUD 中的核心耐久显示清零。

冲击波的停顿效果结束后，Echo 恢复正常行动。

### 屏幕文本

`> TEMPORAL CORE DESTROYED.`

随后：

`> PURGE COMMAND DISABLED.`

停顿片刻。

`> ARCHIVE CYCLE STILL ACTIVE.`

然后：

**`SURVIVE UNTIL 00:00.`**

### 剧情含义

玩家已经破坏负责维持清除命令的时间核心。

但是档案空间仍然处于本次运行周期之中。

旧复制体不会因为核心被摧毁而立即消失，也不会停止攻击。

玩家必须继续存活，直到倒计时结束，档案空间才会解除封锁。

### HUD 变化

核心摧毁后：

- 核心目标标记熄灭。
- `ERASE` 状态仍然显示，但可以增加故障闪烁。
- 倒计时继续减少。
- 场景保留战斗状态。

# 九、第三幕失败演出

## 9.1 玩家死亡

当玩家生命值归零时：

立即停止第三幕计时器和敌人行动。

玩家角色播放现有死亡效果。

屏幕显示：

`> OPERATOR SIGNAL LOST.`

`> INSTANCE TERMINATED.`

**`PURGE FAILED.`**

进入第三幕失败界面。

不播放时间核心摧毁后的结局演出。

### 重试

玩家选择重试后：

- 重置计时器为 `01:30`。
- 重新初始化玩家状态。
- 清空此前的玩家轨迹缓存。
- 重新生成第三幕 Echo。
- 恢复时间核心的初始隐藏状态。
- 重置所有阶段事件与状态。

重新从第三幕开始，不强制返回第一幕。

## 9.2 倒计时归零但核心未被摧毁

当剩余时间达到 `00:00`，如果玩家尚未摧毁时间核心：

停止游戏中的所有战斗行为。

屏幕显示：

`> ARCHIVE CYCLE COMPLETE.`

`> PURGE COMMAND EXECUTED.`

`> OPERATOR INSTANCE ERASED.`

**`ERASURE COMPLETE.`**

玩家角色在原地分解为数字化残影。

随后进入失败结算。

# 十、第三幕游戏机制约束

## 10.1 Echo 随机 AI

第三幕 Echo 使用独立的随机 AI 系统。

- 不读取第一幕最后 30 秒的录像。
- 不使用第二幕的固定幻影回放。
- 独立进行随机移动。
- 随机决定倒带攻击时机。
- 每次攻击生成新的倒带轨迹。
- 倒带攻击前显示明确预警。
- 倒带轨迹在预警开始后锁定。
- 攻击过程中不重新随机改变路径。
- 玩家可以通过已有攻击方式击败 Echo。

每个阶段的 Echo 数量和攻击参数由第三幕独立管理器控制。

被击败的 Echo 可以按照当前阶段的目标数量进行补充。

## 10.2 难度变化

| 剩余时间 | 阶段 | Echo 目标数量 | 主要变化 |
|---|---|---|---|
| 01:30–01:00 | AWAKENING | 2 | 基础随机移动和倒带 |
| 01:00–00:30 | INTERFERENCE | 3 | 缩短倒带攻击间隔 |
| 00:30–00:00 | SYSTEM COLLAPSE | 4 | 最高攻击频率，核心出现 |

以上数量仅适用于第三幕的 Echo 管理，不影响第一幕已经确定的无限敌人生成规则。

## 10.3 时间核心

- 仅在剩余 `00:30` 时出现。
- 不要求先击败指定数量的 Echo。
- 具有 3 点耐久。
- 使用现有玩家攻击系统进行伤害判定。
- 摧毁核心后不立即结束游戏。
- 摧毁后 Echo 继续攻击。
- 只有倒计时归零且玩家仍然存活时才触发胜利。

## 10.4 玩家轨迹

- 玩家轨迹完全由实际操作生成。
- 剧情不规定轨迹数量、密度、长度或形状。
- 不自动生成用于攻击的玩家轨迹。
- 第三幕的 Echo 使用独立轨迹系统。
- Echo 的轨迹不能修改玩家自己的历史记录。
- 视觉残影不参与真实玩家轨迹计算。

## 10.5 场景演出

- 不需要新增复杂人物动画。
- 使用现有几何角色及颜色区别不同实例。
- 剧情效果以 HUD、网格变化、轮廓重影和时间故障为主。
- 演出不得在实际战斗期间遮挡主要攻击轨迹。
- 系统文本不能影响玩家输入。
- 所有倒计时事件只触发一次。

# 十二、第三幕的叙事结构

第三幕共完成四次重要的信息传达。

### 1. 所有复制体都可能被删除

`ALL INSTANCES MARKED FOR ERASURE.`

玩家不再只是按照系统指令删除某个敌人，而是自己也成为清除对象。

### 2. 复制体拥有独立行动能力

`AUTONOMOUS BEHAVIOR DETECTED.`

第三幕的 Echo 不再是录像回放，它们能够主动移动并发动倒带攻击。

### 3. 系统无法区分真正的原版

`ORIGINAL STATUS: UNKNOWN.`

玩家与其他复制体在系统眼中没有本质区别。

### 4. 玩家终止了记录与删除循环

`NO FURTHER OVERWRITING.`

玩家没有变回原始个体，也没有证明自己是唯一真实的人。

他仍然是复制品，但系统已经不能再通过记录、重建和删除来决定他的命运。

# 十三、最终剧情主题

整个游戏的三幕分别对应老式磁带设备的三种操作。

**ACT I — RECORD**

系统记录了玩家的行动，并将玩家的过去制造成新的实例。

**ACT II — REWIND**

玩家重新面对刚刚录制的自己，并被迫亲手将其删除。

**ACT III — ERASE**

玩家发现自己同样来自一份旧记录，而更多的复制体也因为擦除故障而残留下来。

最终，玩家选择破坏执行清除命令的时间核心，终止整个重建与删除循环。

**第三幕结束。**

**REWIND RAMPAGE — THE PAST WAS NEVER ERASED.**
