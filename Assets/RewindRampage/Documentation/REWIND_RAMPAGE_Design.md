# REWIND RAMPAGE
## 基于录像倒带机制的轨迹攻击游戏技术设计文档

**文档版本：** Demo v0.1  
**开发引擎：** Unity 2D / C#  
**游戏类型：** 俯视角动作 / 生存街机 / 轨迹攻击  
**Game Jam 主题：** Old Tech  
**开发规模：** 单人，约 43 小时剩余  
**预期单局时长：** 90 秒

---

# 一、游戏概述

## 1.1 游戏概念

玩家身处一块不断遭受敌人入侵的二维竞技场。

与传统动作游戏不同，玩家无法直接攻击敌人。

玩家拥有一台能够记录自身行动轨迹的古老录像设备。设备会持续记录玩家最近三秒钟的移动位置。

当玩家按下 Space 时，录像设备开始倒带：

1. 玩家沿最近三秒的移动轨迹高速反向运动。
2. 倒带经过的路径转变为具有伤害判定的能量轨迹。
3. 接触轨迹的敌人受到伤害。
4. 一次倒带击杀多个敌人可以产生连击奖励。
5. 倒带结束后，玩家回到此前的位置，重新开始记录。

**核心规则：玩家移动时绘制攻击路线，倒带时执行攻击。**

游戏强调通过主动走位、吸引敌人、规划轨迹与选择倒带时机制造连续击杀。

## 1.2 核心设计目标

- 玩家只需要 WASD 和 Space 即可完成全部操作。
- 不要求记忆复杂指令或按键组合。
- 每次倒带都产生明显的视觉和音效反馈。
- 鼓励玩家主动接近危险区域，而不是一直逃跑。
- 操作技巧来自路径设计和倒带时机，而非复杂的数值系统。
- 90 秒内形成完整的学习、熟练、高潮和结算体验。
- 使用几何图形完成美术，优先验证机制乐趣。

# 二、核心操作机制

## 2.1 玩家移动

使用 WASD 控制玩家在二维平面内自由移动。

| 操作 | 效果 |
|---|---|
| W | 向上移动 |
| A | 向左移动 |
| S | 向下移动 |
| D | 向右移动 |
| Space | 启动倒带攻击 |

允许斜向移动，并对输入方向归一化，确保斜向速度不会超过直线速度。

玩家初始移动速度为 5.5 Unity 单位/秒。

地图具有边界，玩家无法离开竞技场。

正常移动时，玩家不能直接伤害敌人。

## 2.2 移动轨迹记录

录像设备始终记录玩家最近三秒内的移动位置。

轨迹采样间隔建议为 0.05 秒，即每秒记录 20 个位置。

最大存储 60 个采样点。

每个轨迹点包含：

- 世界坐标 Vector2。
- 对应的采样时间。

系统使用固定容量的循环缓冲区或列表保存轨迹。

当记录长度超过三秒时，删除最早的数据，始终只保留最近三秒的路径。

玩家正常移动时，轨迹以蓝色或青色半透明线条显示。

越新的轨迹越亮，越旧的轨迹越暗。

该轨迹不具有伤害能力，只用于提示倒带路线。

## 2.3 倒带启动

玩家按下 Space 时，检查倒带条件：

1. 当前不处于倒带状态。
2. 录像设备不处于冷却状态。
3. 已记录至少一秒的有效移动轨迹。

满足条件后进入 REWIND 状态。

如果不满足条件，不触发倒带，播放简短提示音并显示冷却或录制进度。

初始建议参数：

| 参数 | 数值 |
|---|---|
| 最大录制时长 | 3 秒 |
| 最低有效录制时长 | 1 秒 |
| 倒带移动倍率 | 5 倍 |
| 倒带结束后的冷却 | 2 秒 |
| 倒带期间是否无敌 | 是 |
| 倒带结束后额外无敌 | 0.3 秒 |

例如，玩家记录了三秒轨迹，以五倍速度倒带，完整倒带过程约为 0.6 秒。

## 2.4 倒带过程

启动倒带后：

1. 禁止玩家通过 WASD 改变运动方向。
2. 停止录制新轨迹。
3. 从最新轨迹点开始，沿记录路径逆序移动。
4. 玩家进入无敌状态。
5. 移动轨迹逐段转为黄色或橙色。
6. 黄色轨迹具有攻击判定。
7. 所有敌人的移动暂时冻结。
8. 倒带播放完成后，恢复敌人移动。

为了避免视觉混乱，Demo 中不回滚敌人的位置、生命值或游戏计时。

**倒带只作用于玩家记录的移动轨迹，不是整个世界的时间倒流。**

敌人被冻结是为了提供短暂的动作强调，并简化碰撞判定。

## 2.5 倒带结束

当逆序播放至最早记录的轨迹点时：

- 玩家停止倒带。
- 黄色攻击轨迹迅速消散。
- 玩家恢复正常移动。
- 清空本次消耗的轨迹记录。
- 开始新的轨迹录制。
- 进入两秒倒带冷却。

倒带结束时，玩家的位置为记录片段的起点。

倒带完成后提供 0.3 秒无敌时间，避免玩家刚回到旧位置就立即受到伤害。

# 三、轨迹攻击系统

## 3.1 攻击方式

倒带期间，玩家沿历史路径高速移动。

玩家经过的每段路径都具有攻击判定。

攻击区域可以理解为沿运动轨迹移动的圆形碰撞范围。

推荐初始攻击半径为 0.55 Unity 单位。

因此，即使玩家没有精确撞到敌人，只要经过敌人附近，就可以命中。

## 3.2 碰撞检测

推荐使用线段碰撞判定，避免倒带速度过快造成漏判。

假设本次倒带从 A 点移动到 B 点。

对于场上的每个有效敌人：

1. 取得敌人当前位置 E。
2. 计算 E 到线段 AB 的最近距离。
3. 判断该距离是否小于攻击半径与敌人碰撞半径之和。
4. 如果满足条件，则视为命中。

可以使用点到线段的最近距离计算，也可以采用 Unity Physics2D 的 Cast 类检测方法。

不建议只在每个采样点检测圆形范围，因为高速倒带可能使采样点之间出现碰撞空隙。

## 3.3 同一次倒带的重复命中

为避免玩家原地绕圈时对同一个敌人重复造成大量伤害，规定：

**同一次倒带中，每个敌人最多受到一次伤害。**

系统维护本次倒带已经命中的敌人 ID 集合。

如果再次经过同一敌人，则跳过伤害结算。

一次倒带结束后清空集合。

## 3.4 击杀与连击

Demo 中普通敌人只有 1 点生命值，因此被倒带轨迹命中后立即死亡。

击杀触发：

- 击中闪光。
- 粒子爆炸。
- 击杀音效。
- 得分数字弹出。
- Combo 增长。

连击以单次倒带中的连续击杀数量计算。

建议采用：

第一个敌人：100 分。

第二个敌人：150 分。

第三个敌人：200 分。

之后依次增加 50 分。

单次倒带结束后，显示本次击杀数量和总得分。

例如一次倒带击杀五个敌人：

100 + 150 + 200 + 250 + 300 = 1000 分。

这让玩家主动追求一次性击杀更多敌人。

## 3.5 轨迹形状与玩法策略

轨迹不限制形状。

玩家可以自由画出：

- 直线：快速穿过一排敌人。
- 圆弧：绕过敌群后反向切入。
- 回环：让多个敌人聚集在轨迹附近。
- S 形：覆盖多个方向。
- 折返：围绕局部区域多次穿梭。

轨迹长度受到三秒记录时间限制。

玩家需要决定：

- 什么时候开始录制攻击路线。
- 是否主动接近敌群。
- 怎样让更多敌人处于倒带路径附近。
- 什么时候按下 Space 获得最大收益。

# 四、敌人系统

## 4.1 基础敌人：追踪者

Demo 第一阶段仅实现一种敌人。

敌人由场地边缘生成，持续向玩家当前所在位置移动。

敌人使用简单的方向向量计算移动，无需寻路系统。

每帧计算：

Direction = Normalize(PlayerPosition - EnemyPosition)

然后根据固定速度靠近玩家。

推荐初始速度为 2.5 Unity 单位/秒。

敌人接触玩家时造成一次伤害。

每个敌人拥有一个简单的圆形碰撞体。

## 4.2 敌人与轨迹的关系

敌人会持续追踪玩家，因此自然会聚集在玩家经过的路线附近。

玩家正常移动时，敌人逐渐形成追击队列。

当玩家启动倒带时，攻击轨迹沿之前的路线反向扫过，有机会连续命中追击的敌人。

这将形成游戏的基本节奏：

**逃跑 → 敌人追击 → 绘制路线 → 倒带反杀 → 再次逃跑。**

这比单纯的倒带位移更重要。

## 4.3 敌人生成

EnemySpawner 定期从竞技场边缘生成敌人。

初始生成间隔建议为 1.5 秒。

游戏时间越长，生成间隔逐渐缩短。

初版建议同时存在的敌人上限为 35 个。

敌人生成位置尽可能避开玩家附近，防止突然受到无法预判的碰撞伤害。

## 4.4 进阶敌人（可选）

如果核心玩法验证成功，可以增加第二种敌人：

**漂移者（Drifter）**

漂移者不追踪玩家，而是沿固定方向缓慢穿越场地。

因为其运动方式与追踪者不同，玩家不能简单依靠逃跑就让它自动进入攻击路线。

需要主动改变走位，提前布置倒带路径。

第二种敌人不属于最小可交付范围。

# 五、玩家生存系统

## 5.1 生命值

玩家初始生命值为 3。

正常状态下与敌人接触会损失 1 点生命。

受到伤害后获得约 0.75 秒无敌时间，避免与多个敌人重叠时瞬间死亡。

玩家生命值归零时结束游戏。

## 5.2 倒带无敌

玩家处于 REWIND 状态时不能受到伤害。

敌人被冻结，不会发生正常追踪运动。

因此倒带兼具两个作用：

- 主动攻击。
- 脱离危险位置。

这使得 Space 同时是一种攻击技能和生存技能。

## 5.3 风险与收益

玩家可以频繁使用倒带保命，但短轨迹通常只能击中少量敌人。

如果希望获得高分，就需要等待敌人聚集、延长攻击轨迹，或主动在危险区域移动。

因此玩家需要在保命和高收益之间作出选择。

游戏不强制要求复杂路线才能通关，普通玩家可以通过简单操作获得基础分数。

# 六、游戏流程与难度

## 6.1 游戏模式

采用 90 秒 Score Attack。

玩家的目标是在生存时间内获得尽可能高的分数。

游戏无需关卡切换，全部流程发生在一个固定竞技场中。

## 6.2 游戏前 10 秒

这是最重要的教学阶段。

游戏开始后：

1. 屏幕显示 WASD 移动提示。
2. 玩家开始移动，身后出现明显的蓝色轨迹。
3. 少量慢速敌人开始追踪玩家。
4. 当轨迹记录至少一秒后，Space 图标亮起。
5. 玩家首次按下 Space，沿轨迹倒退并击杀敌人。
6. 游戏显示 REWIND KILL。

第一轮敌人的生成位置应经过专门设计，尽量确保新手第一次倒带就有机会击中敌人。

不采用复杂的独立教学关卡。

## 6.3 难度曲线

| 时间 | 敌人行为 | 玩家主要体验 |
|---|---|---|
| 0–15 秒 | 少量慢速追踪者 | 认识轨迹和倒带 |
| 15–35 秒 | 追踪者逐渐增多 | 主动吸引敌人 |
| 35–60 秒 | 多方向持续生成 | 使用弧线和折返攻击 |
| 60–90 秒 | 敌人密度提高 | 连续击杀，追求高分 |

难度主要通过敌人密度与生成间隔变化，不通过引入新的操作按键增加难度。

## 6.4 结算

时间结束或玩家生命归零时显示：

- 最终得分。
- 总击杀数。
- 最大单次倒带击杀数。
- 最大 Combo。
- 生存时间。

允许立即重新开始。

# 七、Unity 程序架构

## 7.1 PlayerController

职责：

- 读取 WASD 输入。
- 计算玩家正常移动。
- 管理角色受伤和无敌状态。
- 在倒带期间禁用玩家正常控制。

主要字段：

- float moveSpeed
- int currentHealth
- bool isInvulnerable
- PlayerState currentState

主要方法：

- HandleMovement()
- TakeDamage()
- SetInvulnerable()
- SetPlayerState()

## 7.2 TrailRecorder

职责：

- 定期记录玩家位置。
- 保存最近三秒轨迹。
- 维护轨迹的可视化数据。
- 提供逆序轨迹给 RewindController。

主要字段：

- List&lt;TrailPoint&gt; recordedPoints
- float maxRecordDuration
- float sampleInterval
- float sampleTimer

TrailPoint 包含位置和时间。

主要方法：

- RecordPosition()
- GetRecordedPath()
- ClearHistory()
- UpdateTrailVisual()

建议优先使用固定容量循环缓冲区，Demo 中也可以使用 List 实现。

## 7.3 RewindController

职责：

- 检查倒带启动条件。
- 控制玩家沿轨迹逆向移动。
- 管理倒带速度和冷却。
- 触发轨迹攻击判定。
- 处理倒带开始及结束事件。

主要字段：

- float rewindSpeedMultiplier
- float cooldownDuration
- bool isRewinding
- float rewindProgress
- List&lt;Vector2&gt; activePath

主要方法：

- CanRewind()
- StartRewind()
- UpdateRewind()
- FinishRewind()

关键要求：倒带期间不能继续记录玩家位置，否则可能覆盖原始路径，造成重复回放或无限循环。

## 7.4 TrailDamageSystem

职责：

- 检测当前倒带路径是否接触敌人。
- 对敌人造成伤害。
- 避免同一次倒带重复命中。
- 统计本次攻击击杀数。

主要字段：

- float attackRadius
- HashSet&lt;int&gt; hitEnemyIds
- int currentRewindKillCount

主要方法：

- CheckPathSegment(start, end)
- DamageEnemy(enemy)
- ResetHitHistory()
- CalculateComboReward()

## 7.5 EnemyController

职责：

- 追踪玩家。
- 执行敌人移动。
- 判断玩家接触伤害。
- 处理敌人死亡。

主要字段：

- float moveSpeed
- int health
- bool isFrozen

主要方法：

- UpdateChase()
- Freeze()
- TakeDamage()
- Die()

## 7.6 EnemySpawner

职责：

- 控制敌人生成时间与位置。
- 管理场上最大敌人数量。
- 随游戏时间调整敌人生成速度。

## 7.7 GameManager

职责：

- 控制游戏开始和结束。
- 管理 90 秒计时。
- 记录分数与 Combo。
- 管理玩家生命。
- 处理结算和重开。

## 7.8 FeedbackController

职责：

- 显示历史轨迹。
- 执行倒带颜色变化。
- 播放击杀粒子。
- 播放倒带音效。
- 显示得分文字。
- 处理轻微屏幕震动与命中停顿。

反馈系统不直接参与轨迹计算。

# 八、关键技术流程

## 8.1 正常状态

每帧：

1. 读取移动方向。
2. 更新玩家位置。
3. 按采样间隔记录新轨迹点。
4. 更新轨迹显示。
5. 更新敌人追踪与生成。
6. 检查玩家和敌人的碰撞。
7. 检查 Space 输入。

## 8.2 倒带状态

按下 Space 后：

1. 获取当前轨迹记录。
2. 将轨迹固定为本次倒带路径。
3. 禁止玩家正常移动和继续录制轨迹。
4. 设置玩家无敌。
5. 冻结敌人。
6. 按逆序推进玩家轨迹。
7. 对每段已扫过的轨迹执行敌人碰撞检测。
8. 对命中的敌人结算伤害与得分。
9. 播放能量轨迹、击杀反馈。
10. 到达路径起点后结束倒带。
11. 清空旧历史并恢复正常录制。
12. 解除敌人冻结，开始倒带冷却。

不使用全局 Time.timeScale = 0 来冻结整个游戏，避免同时影响倒带动画、冷却和计时逻辑。

应由游戏状态显式控制敌人的更新。

# 九、画面与音效

## 9.1 视觉风格

建议采用深色背景与霓虹几何图形。

| 对象 | 视觉表现 |
|---|---|
| 玩家 | 青色三角形 |
| 追踪敌人 | 红色圆形 |
| 历史轨迹 | 半透明蓝色线条 |
| 倒带攻击 | 黄色或橙色发光轨迹 |
| 敌人死亡 | 几何碎片和短暂闪光 |
| 倒带冷却 | 环形进度条 |

地图可以是简单的深色网格，不需要地形素材。

## 9.2 VHS 主题表现

为了契合 Old Tech，界面可以采用旧式录像机视觉元素。

建议显示：

- REC：正常记录轨迹。
- REW：倒带状态。
- PLAY：恢复正常。
- 磁带长度指示条。
- 轻微扫描线和画面抖动。

不建议一开始制作复杂 VHS Shader。

先通过声音、颜色变化、运动残影和 UI 文本表现录像机主题。

## 9.3 反馈优先级

最高优先级为倒带攻击的反馈。

建议完成：

1. 按下 Space 时播放倒带音效。
2. 玩家高速沿路径后退。
3. 蓝色轨迹瞬间变成金黄色。
4. 命中敌人时产生明显闪光。
5. 多重击杀弹出 Combo 提示。
6. 倒带结束后迅速恢复正常画面。

即使敌人全部使用普通圆形，也应该能感受到攻击的力度。

# 十二、43 小时开发安排

| 开发时间 | 工作内容 |
|---|---|
| 0–3 小时 | WASD 移动、轨迹记录、Space 倒带 |
| 3–8 小时 | 实现轨迹伤害和基础追踪敌人 |
| 8–14 小时 | 完成得分、生命、敌人生成与完整游戏循环 |
| 14–22 小时 | 调整轨迹、攻击范围、敌人速度，验证核心手感 |
| 22–30 小时 | 添加连击、基础特效与音效 |
| 30–36 小时 | VHS 视觉、UI、结算与重新开始 |
| 36–43 小时 | 完整测试、修复 Bug、构建与提交 |

## 必须完成的 MVP

1. 玩家能够自由移动。
2. 身后持续出现可见轨迹。
3. Space 使玩家沿轨迹高速倒退。
4. 倒带经过敌人可以造成伤害。
5. 敌人能够持续追踪玩家。
6. 玩家具有生命值。
7. 游戏具有分数和结算。
8. 倒带具有基本声音与视觉反馈。

其余系统不应阻碍 MVP 的完成。

# 十三、背景故事

游戏发生在一台老式录像设备构建的虚拟竞技场中。

玩家被困在一段不断遭受异常信号入侵的录像里。

普通的行动无法伤害入侵者，因为它们并不属于这段录像原本的内容。

但当录像倒放时，现实与记录之间会发生短暂的冲突，玩家走过的轨迹因此成为能够消除异常信号的武器。

玩家需要利用仅能记录三秒的老旧磁带设备，不断倒带、反击并延长自己的生存时间。

故事只通过简短的开场文字与 VHS 风格 UI 表现，不引入额外的剧情系统。

# 十四、核心设计风险

## 14.1 玩家可能无脑绕圈

如果玩家只需要持续绕圈，再按 Space 就能稳定消灭全部敌人，游戏会很快失去操作深度。

初版先通过三秒轨迹长度限制、敌人追踪速度和倒带冷却控制收益。

如果仍然过于单调，再考虑增加具有不同运动方式的敌人。

## 14.2 倒带可能打不到敌人

如果玩家移动轨迹与敌人实际位置相距过远，倒带会缺少爽感。

初版应让敌人倾向于追踪玩家，并适当扩大轨迹伤害半径。

第一次倒带最好能明显命中敌人。

## 14.3 玩家可能只在危险时倒带

如果倒带主要被用来逃命，玩家不会主动设计攻击路线。

需要让一次倒带击杀多个敌人的奖励足够明显。

同时让场上的敌人数量维持在能够形成群体攻击的水平。

## 14.4 倒带操作可能缺少控制感

倒带过程中玩家无法改变方向。

因此倒带时间不宜过长，建议一次完整回放不超过一秒。

如果倒带显得拖沓，应优先提高回放速度，而不是加入更多按键操作。

# 十五、原型验收标准

本游戏最重要的不是 VHS 美术效果，而是以下三个体验是否成立：

**第一：玩家能否立即理解倒带的攻击效果？**

第一次按下 Space，应清楚看见自身沿过去的路线攻击敌人。

**第二：玩家是否愿意主动设计轨迹？**

在熟悉操作后，玩家应开始主动绕过敌群、改变路线或者吸引敌人聚集，而不只是不断逃跑。

**第三：一次倒带击杀多个敌人是否足够令人满足？**

连续击杀时，应具有明显的声音、画面和得分反馈，让玩家期待下一次更大的连击。

如果这三点成立，再增加敌人类型、特殊轨迹和更多表现效果。

如果这三点不成立，应优先重新设计倒带攻击行为，而不是继续增加外围功能。

**核心设计理念：前进是布局，倒退是攻击。玩家用自己的过去制造武器。**
