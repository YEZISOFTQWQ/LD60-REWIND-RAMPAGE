# REWIND RAMPAGE — v0.2.1
## 第一幕无限重影节点系统增量技术文档

**基于版本：** Demo v0.2  
**修改范围：** 第一幕 ACT I — REC 的轨迹交叉与重影节点系统  
**开发环境：** Unity 2D / C#  
**主要目标：** 移除重影节点的数量上限，允许一次倒带连续引爆全部有效交叉节点。

---

## 一、修改概述

### 1.1 原有机制

在 v0.2 中，玩家正常移动时，历史轨迹发生自交会生成重影节点。

重影节点在倒带经过对应位置时爆炸，造成范围伤害。

原版本存在两个限制：

1. 同时最多保留 2 个有效重影节点。
2. 不同重影节点之间至少相距 0.65 Unity 单位。

这些限制会让复杂的路径失去一部分应有的攻击收益。

### 1.2 新机制

v0.2.1 取消重影节点数量上限。

玩家在最近 3 秒的历史轨迹中，每产生一次符合条件的有效自交，就可以生成一个新的重影节点。

一次轨迹允许存在任意数量的有效节点。

倒带过程中，只要玩家沿历史路线经过对应交叉点，节点便依次爆炸。

不再因为已经存在两个节点而忽略后续交叉。

### 1.3 保留规则

以下规则不变：

- 历史轨迹最多记录最近 3 秒。
- 玩家仍然沿历史轨迹高速逆向移动。
- 重影节点正常移动时不会爆炸。
- 重影节点仅在倒带经过指定位置时触发。
- 每个节点每次录制只允许爆炸一次。
- 重影节点爆炸可以击杀普通敌人。
- 重影节点可以引爆爆裂敌人，并产生连锁反应。
- 玩家进入倒带状态时仍然无敌。
- 倒带结束后清空已消耗的轨迹和节点。

**本次取消的是人为设置的节点数量上限，不是取消三秒录制窗口。**

## 二、无限重影节点的生成规则

### 2.1 基础规则

玩家移动轨迹由连续采样点构成。

每次生成一条新轨迹线段时，检查它与当前有效历史轨迹中的非相邻线段是否相交。

每个有效交点都可以创建重影节点。

例如，一条复杂轨迹产生 5 个有效交点，则生成 5 个节点。

玩家倒带时可以依次触发这 5 个节点，不需要从中选择，也不会自动舍弃较早的节点。

### 2.2 有效交叉判定

保留以下条件：

| 参数 | 建议值 | 作用 |
|---|---:|---|
| 两次经过交点的最小时间差 | 0.6 秒 | 过滤短时间局部抖动 |
| 最小交叉锐角 | 25° | 排除近乎重叠的路线 |
| 轨迹采样间隔 | 0.05 秒 | 沿用现有记录频率 |
| 有效轨迹窗口 | 3 秒 | 沿用现有录制长度 |
| 最大节点数量 | 无 | 取消原有限制 |

对于近似共线、零长度、相邻采样线段以及单纯端点接触，不生成节点。

### 2.3 删除节点距离限制

移除原有的最小节点间距 0.65 单位规则。

原因是：两条不同路径可能在空间中非常接近的位置形成不同的有效交点。

如果使用较大的距离阈值合并节点，会导致合法交叉被错误忽略，实际形成隐藏的数量限制。

新版本只处理重复检测：

**同一个几何交叉事件不得重复生成节点，但不同的有效交叉事件即使距离很近，也可以分别生成节点。**

重复判断应优先依据参与交叉的轨迹段 ID、交点参数和经过时间。

对于发生在公共顶点附近的数值重复结果，可使用很小的坐标容差进行归并。

不允许用宽范围的空间距离检测合并不同的有效交点。

## 三、节点生命周期

### 3.1 节点数据

建议继续使用 GhostNode 数据结构，字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| NodeId | int | 唯一标识 |
| Position | Vector2 | 交叉世界坐标 |
| EarlierTime | float | 较早一次经过交点的时间 |
| LaterTime | float | 较晚一次经过交点的时间 |
| EarlierSegmentId | int | 较早轨迹段 ID |
| LaterSegmentId | int | 较晚轨迹段 ID |
| IsActive | bool | 节点是否仍有效 |
| HasTriggered | bool | 节点是否已经爆炸 |

其中 EarlierTime、LaterTime 应当是线段交点的插值时间，而非简单使用线段终点时间。

这样能够在高速倒带时准确判断交点经过顺序。

### 3.2 动态节点集合

原先使用最多两个节点的固定集合。

新版本修改为可动态扩展的集合：

ActiveGhostNodes：保存所有当前有效重影节点。

不设置 MaxGhostNodes 数量限制。

当 TrailIntersectionDetector 检测到一个有效交叉时，直接加入集合。

### 3.3 节点过期

由于录像系统只保存最近三秒，旧轨迹需要逐渐过期。

如果节点所依赖的较早轨迹段已经从有效历史中移除，则节点也应失效。

判定时应检查 EarlierTime 是否仍处于当前可回放轨迹窗口内，同时确认对应轨迹段依然有效。

不能让节点永久保留在地图上。

### 3.4 倒带启动

玩家按下 Space 时：

1. 固定当前有效轨迹。
2. 固定本次可触发的全部重影节点。
3. 停止正常轨迹记录和交叉检测。
4. 将节点按 LaterTime 从晚到早排序。
5. 开始沿历史路径逆向移动。

节点集合在倒带期间不再新增内容。

### 3.5 倒带结束

倒带结束时：

- 清除本次录制生成的所有节点。
- 清空节点已触发状态及关联索引。
- 清空已经消耗的历史轨迹。
- 重新开始正常轨迹记录。

## 四、多个重影节点的连续触发

### 4.1 触发条件

倒带时，RewindController 使用历史时间游标表示当前回放位置。

当回放时间从 T1 逆向推进到 T0 时，检查是否存在 LaterTime 位于该时间区间内的未触发节点。

如果存在，则按照倒带经过的先后顺序依次触发。

例如：

本次轨迹中存在四个重影节点：

- N1：LaterTime = 1.2 秒
- N2：LaterTime = 1.7 秒
- N3：LaterTime = 2.1 秒
- N4：LaterTime = 2.8 秒

倒带从 3.0 秒开始。

实际触发顺序应为：

N4 → N3 → N2 → N1。

节点依次爆炸，而不是同时爆炸。

### 4.2 同一帧经过多个节点

由于倒带速度为正常移动速度的 5 倍，单帧可能跨越多段历史轨迹。

因此不得使用简单的「当前玩家位置距离节点小于某阈值」作为唯一触发条件。

推荐采用历史时间区间检测：

如果一个节点的 LaterTime 位于上一次与当前回放时间之间，则说明倒带经过了该节点。

即使单帧跨越多个节点，也必须触发所有对应事件。

可以在倒带开始时将节点排序，并使用索引依次消费。

这种方式能够避免每帧遍历所有节点。

### 4.3 爆炸效果

每个节点爆炸时：

1. 将 HasTriggered 设置为 true。
2. 在交叉位置生成范围冲击波。
3. 查询范围内敌人。
4. 执行伤害判定。
5. 将被击杀的爆裂敌人产生的爆炸加入队列。
6. 播放节点消失与冲击波动画。
7. 继续推进倒带路径。

每个节点独立触发一次爆炸。

**不设置一次倒带可触发的爆炸次数上限。**

### 4.4 与普通轨迹伤害的关系

普通倒带轨迹伤害仍然正常生效。

同一敌人在同一次倒带中可能同时受到轨迹、节点和爆裂敌人爆炸影响。

为了与 v0.1 的单次倒带命中规则保持一致：

- 每个节点都必须正常爆炸。
- 已死亡的敌人不得重复死亡或重复计分。
- Demo 中同一敌人在单次倒带内最多受到一次有效伤害。
- Boss 战仍沿用原先的单次倒带伤害上限，不受本次修改影响。

因此，节点数量无限并不意味着同一敌人会被重复击杀。

多个节点的主要收益是扩大攻击覆盖范围，以及触发更多爆裂敌人连锁。

## 五、Unity 系统修改

### 5.1 TrailIntersectionDetector.cs

这是本次主要修改的脚本。

**删除或停用：**

- MaxGhostNodes = 2 的数量限制。
- ActiveGhostNodes.Count 达到上限时直接返回的逻辑。
- 原有 0.65 单位的不同节点最小距离过滤。

**保留：**

- 线段相交检测。
- 交叉角度检测。
- 经过时间间隔检测。
- 相邻线段过滤。
- 轨迹过期处理。

**新增或调整：**

- 每条新线段与全部有效历史线段进行检测。
- 一个新线段可以产生多个交叉结果。
- 所有有效结果均进入节点集合。
- 使用轨迹段 ID 与交点参数过滤重复事件。

不要在找到第一个有效交点后立即结束检测循环。

### 5.2 GhostNodeController.cs

删除固定节点数量的管理方式。

改为管理动态节点集合。

建议公开接口：

- RegisterNode(GhostNode node)
- RemoveNode(int nodeId)
- GetActiveNodes()
- FreezeNodesForRewind()
- ClearAllNodes()

节点视觉对象应与节点逻辑数据分离。

可以使用对象池管理显示对象，但不能因为对象池暂时没有空闲对象，就忽略一个合法的节点逻辑。

### 5.3 RewindController.cs

保留现有高速倒退方式。

新增或修改：

- 倒带开始时获取全部有效节点。
- 对节点按 LaterTime 降序排序。
- 维护下一待触发节点索引。
- 每次推进历史时间时触发全部经过的节点。
- 倒带结束后清理本次节点数据。

禁止因为同一帧已经触发一个节点，就跳过剩余节点。

重影节点的触发也不能中断倒带运动。

### 5.4 ExplosionResolver.cs

继续复用已有范围爆炸系统。

无需改变爆裂敌人的基础规则。

但必须确认：

- 同一帧允许收到多个独立爆炸事件。
- 爆炸事件队列没有固定数量上限。
- 死亡事件具有重复执行保护。
- 连锁爆炸结束后队列能够正确清空。

建议统一使用事件队列，而不是在多个节点同时爆炸时相互递归调用伤害处理。

### 5.5 FeedbackController.cs

可能同时存在多个节点和多个爆炸特效。

建议通过对象池重用：

- 重影节点 Sprite。
- 冲击波 Sprite。
- 爆炸粒子。
- 得分提示。

逻辑事件全部保留。

视觉方面可以降低单个冲击波的粒子数量，以防复杂轨迹产生大量同时播放的特效。

## 六、性能设计

### 6.1 交叉检测性能

当前轨迹采样间隔为 0.05 秒。

三秒录制窗口大约包含 60 个采样点和约 59 条线段。

每次加入新线段，只需与窗口内其他有效线段比较。

单次新增线段的交叉检测复杂度为 O(N)，N 为有效历史线段数量。

在当前规模下，不需要空间分区、四叉树等复杂加速结构。

### 6.2 节点数量

新版本没有显式数量上限。

但节点仍受到以下自然约束：

- 三秒轨迹窗口。
- 轨迹采样密度。
- 交叉时间间隔。
- 交叉角度要求。
- 玩家实际移动路径。

因此，节点不会无条件无限积累。

设计上不人为限制数量；实现上根据真实生成的数据动态处理。

### 6.3 倒带触发性能

倒带开始时对所有有效节点排序。

排序复杂度为 O(K log K)，K 为有效节点数量。

之后使用索引按顺序触发，每个节点只遍历和消费一次。

整次回放中的节点触发处理复杂度为 O(K)，不包括实际爆炸范围查询。

不推荐每帧对所有节点重新进行距离检测。

### 6.4 连续爆炸优化

一次倒带可能在很短时间内触发多个节点爆炸。

要求：

- 逻辑攻击事件不得丢失。
- 所有敌人死亡必须正确结算。
- 所有爆裂敌人连锁必须正常处理。
- 视觉特效可以使用对象池和轻量化动画降低开销。

不设置隐藏的「每帧最多处理两个节点」之类的限制。

如果极端情况下出现明显性能问题，应优先优化碰撞查询和特效，而不是重新设置节点数量上限。

## 九、版本验收标准

v0.2.1 完成后，应满足以下要求：

1. 玩家能够通过自由移动制造任意数量的有效交叉节点。
2. 生成节点时不再受到固定数量上限限制。
3. 所有有效节点都能够被玩家清楚看见。
4. 倒带沿历史路线依次触发全部有效节点。
5. 多节点爆炸能够正常击杀敌人和引发连锁。
6. 复杂轨迹不会造成重复死亡或重复计分。
7. 高速倒带不会漏掉任何经过的节点。
8. 录制窗口过期与状态重置能够正确清理节点。
9. 不修改原有移动、倒带轨迹攻击和冷却机制。
10. 第二幕和第三幕的现有规则不受本次第一幕修改影响。

## 十、设计目标

本次改动主要鼓励玩家使用更加复杂的路线。

玩家不再需要考虑重影节点数量是否已达到上限。

只要一条轨迹产生多个真实的有效交叉，玩家便可以获得多个攻击爆点。

例如玩家在三秒内画出复杂的 8 字形或连续交叉路线，启动倒带时，多个交叉位置将依次爆炸，并可能进一步引爆场上的爆裂敌人。

玩家可以用更高的路线规划能力换取更大的攻击范围和连锁收益。

**设计原则：不限制玩家能够创造多少个有效交叉，让复杂的时间轨迹自然转化为更强的攻击。**
