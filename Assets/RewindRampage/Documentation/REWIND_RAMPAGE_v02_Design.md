# REWIND RAMPAGE — Demo v0.2
## 轨迹交叉与连锁爆炸系统增量技术设计文档

**版本：** v0.2  
**基于版本：** Demo v0.1  
**开发引擎：** Unity 2D / C#  
**开发目标：** 在现有倒带斩击玩法上增加路线规划和连锁击杀深度  
**修改范围：** 重影节点、爆裂敌人及必要的系统接口调整

---

# 一、版本更新概述

## 1.1 保留现有机制

以下 v0.1 功能全部保留：

- WASD 控制玩家自由移动。
- 持续记录最近 3 秒的移动轨迹。
- Space 触发沿历史轨迹高速倒退。
- 倒带期间玩家无敌，敌人停止运动。
- 玩家沿轨迹逆向移动时，对路径附近的敌人造成伤害。
- 同一次倒带中，同一敌人最多受到一次有效攻击。
- 倒带结束后返回历史路径起点。
- 2 秒倒带冷却。
- 敌人追踪、玩家生命、得分、Combo 和游戏结算。

不修改基础移动速度、录制时间、倒带速度和基础攻击半径。

**特别说明：v0.2 仍然采用逐段倒退攻击，不允许将整条历史轨迹一次性转变为瞬间范围攻击。**

## 1.2 新增功能

本次仅增加两项主要机制。

**功能 A：重影节点（Double Exposure）**

当玩家的有效移动轨迹发生自交时，在交叉位置生成一个重影节点。

重影节点不会在生成时造成伤害。

当玩家发动倒带，并沿历史轨迹逆向运动至对应交叉位置时，该节点产生一次范围冲击波。

**功能 B：爆裂敌人（Volatile Enemy）**

增加一种移动速度较慢的特殊敌人。

爆裂敌人死亡时产生范围爆炸，对周围敌人造成伤害。

被爆炸击杀的其他爆裂敌人会继续爆炸，形成连锁反应。

## 1.3 核心设计原则

本次更新不要求玩家学习额外按键。

玩家仍然使用 WASD 和 Space，但可以通过路线形状及敌人分布创造不同的攻击结果。

新增系统应当强化：

1. 主动形成轨迹交叉。
2. 利用倒带引爆交叉点。
3. 通过爆裂敌人扩大攻击范围。
4. 通过连续击杀获得明确的即时奖励。

# 二、功能 A：重影节点系统

## 2.1 基本规则

玩家正常移动时，TrailRecorder 持续记录玩家的位置。

当新增轨迹线段与更早的有效轨迹线段发生非相邻交叉时，在交点生成一个重影节点。

重影节点具有以下特征：

- 只存在于最近三秒的有效历史轨迹中。
- 表现为轨迹上的金色发光节点。
- 正常移动时没有伤害能力。
- 只有倒带真正经过指定交点时才会触发。
- 每个节点只能触发一次。
- 触发后释放圆形范围冲击波。
- 同一次录制最多保留两个有效重影节点。

## 2.2 交叉检测

将移动轨迹表示为按时间排列的点：

P0、P1、P2……Pn。

相邻两个点组成一条轨迹线段：

Si = Pi → Pi+1。

每次 TrailRecorder 新增轨迹点时，得到最新线段 Sn。

系统检查 Sn 是否与历史中的非相邻线段 Si 发生相交。

如果两段轨迹存在有效交点，且满足规定条件，则生成重影节点。

### 有效交叉条件

同时满足：

1. 两条线段在二维空间内真正相交。
2. 两段轨迹不属于相邻采样线段。
3. 交叉处对应的两次经过时间至少间隔 0.6 秒。
4. 两条线段的交叉锐角不小于 25°。
5. 线段不能是近似完全重叠的共线段。
6. 交点与其他有效重影节点距离不小于 0.65 单位。
7. 当前有效重影节点总数小于 2。

不满足条件时，不生成新节点。

时间间隔限制用于防止玩家在原地微小抖动时意外制造大量重影节点。

角度限制用于排除近乎重合的折返路径，鼓励玩家主动形成明显的交叉路线。

### 线段交叉计算

对于二维线段 AB 与 CD，可以使用参数形式：

P = A + t(B - A)

Q = C + u(D - C)

求出参数 t、u。

当两者均处于线段范围内部且交点相同时，认为发生交叉。

若两条线段平行、共线或近似平行，则直接忽略。

建议将计算逻辑封装为独立的二维线段求交工具方法。

## 2.3 节点生成时机

重影节点在**正常录制阶段**产生。

例如：

1. 玩家从左下方向右上方移动。
2. 随后绕行至右下方。
3. 再从右下方向左上方移动。
4. 新轨迹与之前的轨迹相交。
5. 相交处立即显示金色重影节点。

此时没有伤害，也不暂停敌人的行动。

玩家可以继续移动，或者选择发动倒带。

## 2.4 节点与轨迹绑定

不能只保存节点的世界坐标。

每个重影节点需要记录：

- 唯一节点 ID。
- 交叉世界坐标。
- 较早轨迹段的交点时间。
- 较晚轨迹段的交点时间。
- 当前有效性。
- 本次倒带是否已经触发。

其中，较晚交点时间用于倒带触发判定。

原因是：同一个交点在完整历史轨迹中可能被经过两次。

为保证行为确定，本版规定：

**倒带从最新记录向过去回放，第一次经过该节点对应的较晚轨迹段时触发冲击波。**

随后无论玩家是否再次经过交点，都不会重复触发。

## 2.5 轨迹过期处理

由于 v0.1 只保存最近三秒的轨迹，旧轨迹会逐渐被移除。

当重影节点依赖的较早轨迹段已经超出录制窗口时，该节点立即失效并消失。

即使交点位置仍然存在于较新的轨迹中，也不能继续保留原节点。

推荐通过轨迹时间戳判断节点是否过期，而不是依赖 List 中固定的数组下标。

避免循环缓冲区删除旧采样点后，节点引用错误的轨迹段。

## 2.6 倒带触发

玩家按下 Space，开始执行 v0.1 的轨迹逆向回放。

RewindController 在推进当前轨迹段时，检查是否穿过尚未触发的重影节点的较晚交点时间。

如果经过：

1. 标记节点为已触发。
2. 在节点世界位置生成范围冲击波。
3. 检测冲击波范围内的敌人。
4. 对敌人造成一次伤害。
5. 触发视觉和声音反馈。
6. 移除节点的可交互状态。

重影节点的爆炸不会终止玩家倒带。

玩家继续沿原始历史轨迹向过去移动。

如果单帧倒带跨越多条轨迹线段，系统必须逐段检查，不能只检查当前和最终位置。

## 2.7 范围伤害

重影节点触发后，以交点为圆心释放冲击波。

初始爆炸半径为 1.5 Unity 单位。

普通敌人进入范围后立即死亡。

爆裂敌人进入范围后同样受到一次伤害，如果因此死亡，则触发对应的敌人爆炸。

同一次重影节点冲击波对每个敌人只生效一次。

范围检测建议采用 Physics2D.OverlapCircleNonAlloc 或项目现有的敌人集合距离检测。

如果现有项目采用新版 Unity 的其他非分配式查询接口，也可以使用等价实现。

## 2.8 节点数量限制

同一时刻最多存在两个有效重影节点。

当达到上限时，后续交叉不生成新的节点。

旧节点因轨迹过期而消失后，才允许创建新的节点。

Demo v0.2 不加入节点升级、节点叠加或多个节点融合机制。

# 四、功能 B：爆裂敌人系统

## 4.1 基本定义

新增敌人类型 VolatileEnemy。

它继承或复用原有敌人的基础移动、生命、受伤及死亡系统。

与普通追踪敌人的差异在于：

- 移动速度较慢。
- 外观采用橙红色发光圆形或六边形。
- 生命值仍为 1。
- 死亡时产生范围爆炸。
- 爆炸可击杀其他普通敌人和爆裂敌人。

爆裂敌人不是远程攻击单位。

它仍然追踪玩家，只是在死亡时具有额外效果。

## 4.2 移动规则

爆裂敌人使用原有 EnemyController 的追踪逻辑。

移动方向仍为：

Normalize(PlayerPosition - EnemyPosition)

区别仅在于移动速度。

普通敌人速度保持 v0.1 的 2.5。

爆裂敌人建议速度为 1.8。

较低速度使爆裂敌人能够成为场景中的临时攻击目标，让玩家主动吸引其他敌人靠近它。

## 4.3 爆炸触发条件

当 VolatileEnemy 的生命值降至零时，立即触发爆炸事件。

能够造成爆裂敌人死亡的来源包括：

1. 玩家倒带轨迹的直接命中。
2. 重影节点冲击波。
3. 其他爆裂敌人的爆炸。

爆裂敌人因任何有效伤害死亡后，均可触发一次爆炸。

每个爆裂敌人死亡后最多触发一次爆炸。

## 4.4 爆炸判定

爆炸以敌人死亡位置为圆心。

推荐初始半径为 1.75 Unity 单位。

爆炸范围内的普通敌人受到 1 点伤害。

爆炸范围内的其他爆裂敌人同样受到 1 点伤害，并可能继续爆炸。

玩家不受爆裂敌人死亡爆炸的伤害。

这样可以避免玩家因为成功击杀敌人而受到惩罚。

爆炸效果不改变玩家位置，不施加击退或物理冲量。

## 4.5 连锁爆炸

假设场景中存在三个相互靠近的爆裂敌人 A、B、C。

玩家倒带击杀 A 后：

1. A 死亡，生成爆炸。
2. B 位于 A 的爆炸范围内，受到伤害并死亡。
3. B 产生第二次爆炸。
4. C 位于 B 的爆炸范围内，受到伤害并死亡。
5. C 产生第三次爆炸。
6. 周围普通敌人受到对应范围伤害。

这形成自动连锁。

为保证逻辑稳定，建议使用**爆炸事件队列**，不要在死亡事件中无限递归调用其他敌人的死亡逻辑。

### 事件队列流程

1. 当一个爆裂敌人死亡时，立即将其标记为 Dead。
2. 将它的爆炸事件加入 ExplosionQueue。
3. ExplosionResolver 逐个取出待处理爆炸。
4. 查询当前仍然存活的敌人。
5. 对范围内敌人执行伤害。
6. 如果新的爆裂敌人死亡，将新的爆炸事件追加至队列。
7. 持续处理，直到队列为空。

每个爆裂敌人只能向队列添加一次死亡爆炸事件。

同一个敌人如果已经死亡，则后续爆炸不能再次触发它的死亡处理。

这样可以防止：

- A 与 B 互相重复触发爆炸。
- 同一敌人被重复计分。
- 连锁爆炸重复生成粒子。
- 大量递归调用造成堆栈问题。

Demo 中建议在逻辑上立即完成连锁结算，视觉效果则可以依次播放。

## 4.6 得分与 Combo

所有有效击杀都应进入 v0.1 的统一计分系统。

包括：

- 倒带轨迹直接击杀。
- 重影节点范围击杀。
- 爆裂敌人连锁击杀。

原有单次倒带击杀分数规则保持不变：

第一杀 100 分，第二杀 150 分，第三杀 200 分，以此类推。

连锁爆炸产生的击杀计入当前倒带的击杀数量。

建议在 UI 上显示本次连锁爆炸击杀数量，例如：

CHAIN ×5

但是本版不增加额外的连锁得分倍率，以免同时存在两套复杂计分规则。

# 六、两个新增机制的交互关系

## 6.1 轨迹攻击击杀爆裂敌人

玩家在正常移动时绘制轨迹。

启动倒带后，如果攻击轨迹直接击中爆裂敌人：

- 爆裂敌人死亡。
- 在死亡位置产生爆炸。
- 周围其他敌人受到伤害。
- 如果存在其他爆裂敌人，可能形成连锁反应。

该过程不依赖重影节点。

## 6.2 重影节点引爆爆裂敌人

当倒带经过重影节点时：

- 节点释放冲击波。
- 范围内的爆裂敌人受到伤害。
- 死亡的爆裂敌人产生自己的爆炸。
- 爆炸继续影响周围敌人。

因此，玩家可以利用重影节点间接攻击原本不在倒带路径上的敌人。

这是本次版本最重要的机制联动。

## 6.3 多个伤害源同时作用

在同一帧内，某个敌人可能同时处于：

- 倒带轨迹攻击范围。
- 重影节点冲击波范围。
- 爆裂敌人爆炸范围。

必须通过统一的伤害和死亡系统处理。

一个敌人只允许从 Alive 变为 Dead 一次。

死亡事件只分发一次。

得分只结算一次。

如果敌人在被重影节点击杀后，又处于轨迹攻击范围，则轨迹攻击直接忽略已经死亡的对象。

对于同一倒带时间段，建议统一处理顺序：

1. 轨迹直接伤害。
2. 到达的重影节点触发冲击波。
3. 处理爆裂敌人爆炸事件队列。
4. 完成得分与 Combo 统计。
5. 继续下一段倒带移动。

# 七、Unity 增量系统架构

## 7.1 新增 TrailIntersectionDetector

**用途：** 检测玩家移动轨迹的有效自交点。

新增脚本：

TrailIntersectionDetector.cs

主要职责：

- 接收 TrailRecorder 新增的轨迹线段。
- 遍历当前有效历史轨迹线段。
- 检查有效交叉。
- 过滤相邻、时间过近和近似共线的轨迹段。
- 生成 GhostNode 数据。
- 检查旧节点是否仍在有效轨迹窗口中。

建议公开接口：

| 方法 | 功能 |
|---|---|
| OnTrailSegmentAdded | 新增轨迹段时检查交叉 |
| TryGetIntersection | 计算两条线段是否相交 |
| ValidateIntersection | 检查时间、角度和距离限制 |
| PruneExpiredNodes | 移除依赖已过期轨迹的节点 |
| GetActiveNodes | 返回有效节点集合 |
| ClearNodes | 清理当前节点 |

该类不负责造成伤害。

## 7.2 新增 GhostNode 数据结构

建议定义 GhostNode 类或结构体。

| 字段 | 类型 | 说明 |
|---|---|---|
| NodeId | int | 唯一 ID |
| Position | Vector2 | 交叉坐标 |
| EarlierTime | float | 较早轨迹经过时间 |
| LaterTime | float | 较晚轨迹经过时间 |
| IsActive | bool | 是否有效 |
| HasTriggered | bool | 是否已触发 |

为了避免轨迹数组移动导致引用失效，推荐使用时间标识轨迹位置。

实际触发时依据 LaterTime 判断倒带是否到达交点。

## 7.3 新增 GhostNodeController

新增脚本：

GhostNodeController.cs

职责：

- 创建重影节点视觉对象。
- 更新节点显示。
- 响应节点触发事件。
- 播放冲击波效果。
- 将范围攻击请求提交给统一伤害系统。

建议接口：

- SpawnNode()
- TriggerNode()
- RemoveNode()
- ClearAllNodes()

视觉节点与逻辑节点应分离。

不要使用 MonoBehaviour GameObject 本身保存唯一的轨迹交叉判定状态。

## 7.4 新增 ExplosionResolver

新增脚本：

ExplosionResolver.cs

职责：

- 接收范围爆炸请求。
- 维护 ExplosionQueue。
- 检测范围内敌人。
- 统一调用敌人伤害接口。
- 处理连锁爆炸。
- 防止重复死亡与重复爆炸。

建议接口：

- EnqueueExplosion(position, radius, damage, source)
- ProcessPendingExplosions()
- ClearPendingExplosions()

爆炸事件建议包含：

- 爆炸中心。
- 爆炸半径。
- 爆炸伤害。
- 爆炸来源。
- 对应倒带攻击 ID。

记录来源便于统计单次倒带造成的击杀。

## 7.5 新增 VolatileEnemyController

新增脚本：

VolatileEnemyController.cs

建议在现有 EnemyController 上增加可选的死亡效果组件。

职责：

- 提供爆裂敌人参数。

- 在死亡位置生成爆炸请求。
- 触发爆炸视觉反馈。

# 八、现有系统修改点

## 8.1 TrailRecorder.cs

保留现有记录方式。

需要增加：

1. 轨迹采样点时间信息的访问能力。
2. 新增轨迹段事件。
3. 当前有效轨迹起始时间的访问能力。
4. 轨迹清除时通知重影节点系统。

如果 v0.1 已存储带时间戳的轨迹点，则无需改变存储结构。

关键要求：

新增交叉检测不能改变三秒记录窗口及现有轨迹渲染行为。

## 8.2 RewindController.cs

保留现有沿历史轨迹逆向移动的逻辑。

增加：

- 倒带开始时固定本次有效重影节点列表。
- 在推进倒带路径时检测是否经过节点触发时间。
- 对达到触发位置的节点发送 TriggerNode 事件。
- 倒带结束后清空未使用的旧节点。

当单帧跨越多个轨迹段时，要依次检查所有经过的节点。

重影节点的触发不能改变倒带路径与移动速度。

## 8.3 TrailDamageSystem.cs

原有轨迹伤害判定保留。

增加统一的伤害调用接口，供以下系统共同使用：

- 轨迹直接攻击。
- 重影节点冲击波。
- 爆裂敌人爆炸。

原本只服务于轨迹攻击的已命中敌人集合，仍可保留。

但敌人死亡去重应由统一 EnemyController 负责，不能仅依赖 TrailDamageSystem。

## 8.4 EnemyController.cs

建议增加：

- IsDead 状态。
- 统一 TakeDamage 接口。
- OnDeath 事件。
- 死亡原因参数。

所有伤害来源必须调用同一套生命与死亡逻辑。

如果敌人已经死亡，则忽略新的伤害。

在调用死亡事件前，将敌人标记为 Dead。

不要在触发死亡事件前立即 Destroy GameObject，否则其他系统可能无法读取死亡位置等必要信息。

## 8.5 EnemySpawner.cs

增加 Volatile 敌人生成配置。

初始阶段只生成普通敌人。

达到指定游戏时间后，允许一定概率生成爆裂敌人。

同屏爆裂敌人最多三个。

复用现有生成区域与总敌人上限。

## 8.6 GameManager.cs

保留现有计时、生命和结算逻辑。

统一接收敌人死亡事件，根据当前倒带中的击杀序号结算分数。

建议新增两个统计量：

- TotalGhostNodeTriggers：重影节点触发次数。
- TotalChainKills：由爆裂敌人爆炸直接造成的击杀次数。

结算界面可选择显示这两项数据。

## 8.7 FeedbackController.cs

新增：

- 重影节点生成时的金色闪光。
- 节点触发时的圆形冲击波。
- 爆裂敌人死亡时的橙色范围爆炸。
- 连锁击杀的 CHAIN 提示。
- 不同爆炸来源的音效变化。

不需要制作复杂动画资源。

建议使用 SpriteRenderer 缩放、透明度变化和简单粒子系统。

# 九、系统执行顺序

## 9.1 正常移动阶段

1. PlayerController 更新玩家位置。
2. TrailRecorder 保存新的位置采样点。
3. 如果形成新轨迹段，通知 TrailIntersectionDetector。
4. 检测新线段与历史线段是否形成有效交叉。
5. 满足规则时创建重影节点。
6. 删除依赖已过期轨迹的节点。
7. GhostNodeController 更新节点视觉状态。
8. 原有敌人追踪和受击系统正常运行。

## 9.2 倒带阶段

1. 玩家按下 Space。
2. RewindController 获取本次历史轨迹。
3. 固定本次可触发的有效重影节点集合。
4. 进入倒带状态并冻结敌人。
5. 沿历史轨迹逆向推进玩家位置。
6. 对经过的轨迹段执行原有伤害判定。
7. 判断是否经过重影节点的较晚交点时间。
8. 如果到达，触发节点冲击波。
9. 爆裂敌人死亡后，提交死亡爆炸事件。
10. ExplosionResolver 处理全部待执行爆炸。
11. GameManager 统一统计击杀与得分。
12. 继续倒带，直到历史路径回放完成。
13. 清理已消耗的轨迹与重影节点。
14. 解除敌人冻结，恢复 v0.1 的正常状态与冷却。

# 十、生成规则与游戏难度

本次版本不修改游戏总时长。

沿用 90 秒 Score Attack。

建议按以下节奏引入新增内容。

| 时间 | 新增内容 | 目的 |
|---|---|---|
| 0–15 秒 | 仅普通追踪敌人 | 保留原版学习阶段 |
| 15–25 秒 | 允许轨迹交叉生成重影节点 | 引导玩家尝试画交叉路线 |
| 25–45 秒 | 首次生成爆裂敌人 | 让玩家认识范围击杀 |
| 45–65 秒 | 爆裂敌人与重影节点共同出现 | 鼓励组合使用 |
| 65–90 秒 | 提高敌人密度和爆裂敌人生成比例 | 追求大规模连锁击杀 |

游戏中不必弹出长篇文字教程。

首次生成重影节点时，可在附近显示：

DOUBLE EXPOSURE

倒带引爆后显示：

首次通过爆裂敌人产生连锁击杀时显示：

# 十三、开发注意事项

## 13.1 不要直接按轨迹采样点生成爆炸

节点必须来自两条有效历史线段的真实交点。

如果只判断玩家是否接近以前的某个采样点，玩家简单折返就可能错误地产生重影节点。

## 13.2 不要在整条轨迹上立即结算所有节点

重影节点必须等到倒带实际经过对应位置时才释放冲击波。

否则重影节点会变成另一种瞬间全轨迹攻击，偏离 v0.1 的核心设计。

## 13.3 避免死亡事件重复执行

EnemyController 的死亡处理应当是幂等的。

同一敌人无论同时收到多少次伤害，只允许：

- 触发一次死亡。
- 产生一次死亡特效。
- 结算一次分数。
- 对于爆裂敌人，生成一次死亡爆炸。

## 13.4 连锁爆炸使用事件队列

所有爆炸事件通过统一队列处理，不允许各个爆裂敌人脚本直接无限嵌套调用彼此的死亡方法。

## 13.5 控制屏幕反馈密度

连续爆炸时可以出现多个爆炸光环，但不建议每次爆炸都使整个游戏停顿。

如果需要 Hit Stop，建议仅在第一次重影节点爆炸或重大连锁时添加非常短暂的停顿。

连续爆炸期间不能影响倒带状态机的稳定性。

## 13.6 保持功能开关

建议为以下功能提供 Inspector 开关：

- EnableGhostNodes
- EnableVolatileEnemies
- EnableChainExplosions

便于分别测试原版、单独新增机制和两个机制组合后的手感。

# 十四、v0.2 验收标准

本版本完成后应满足：

1. 玩家可以通过明显的轨迹交叉，稳定制造重影节点。
2. 正常移动阶段不会因为交叉直接伤害敌人。
3. 玩家沿历史轨迹倒退经过节点时，产生明确的范围爆炸。
4. 重影节点的触发与普通轨迹攻击可以同时存在。
5. 爆裂敌人死亡能够击杀周围敌人。
6. 多个爆裂敌人可以形成可预测的连锁反应。
7. 所有连锁击杀都正确计入同一次倒带的得分和 Combo。
8. 不存在重复死亡、重复爆炸或重复计分问题。
9. 原有移动、轨迹记录、倒带、生命和结算系统正常运行。
10. 不依赖新操作按键即可体验全部新增玩法。

**版本设计目标：保留“前进布局、倒退攻击”的基础玩法，通过轨迹交叉和连锁爆炸，让玩家用更有目的性的走位创造更大规模的击杀。**
