# REWIND RAMPAGE — Demo v0.3
## 第二幕：PLAYBACK — 抹除过去
### Unity 增量技术设计文档

**基于版本：** Demo v0.2.1  
**开发引擎：** Unity 2D / C#  
**新增阶段：** ACT II — PLAYBACK  
**挑战时长：** 30 秒  
**核心目标：** 击杀上一局的自己  
**开发原则：** 复用现有轨迹记录、倒带伤害与重影节点系统，不重写第一幕

# 一、版本目标

## 1.1 第二幕概述

玩家在第一幕中生存 90 秒。

游戏在此期间持续记录玩家的实际位置、运动状态、倒带攻击路径及重影节点爆炸事件。

当第一幕计时达到 90 秒时，游戏不直接进入结算，而是执行全局录像倒带转场。

随后进入第二幕。

场上的普通敌人和爆裂敌人全部消失，竞技场恢复初始状态。

一个由第一幕录像生成的幽灵角色出现在场上。

幽灵角色即上一局的玩家。

幽灵严格按照已录制的数据移动、倒带和发动攻击。

玩家需要在 30 秒内使用自己的倒带攻击击杀幽灵。

如果成功，进入后续剧情阶段；如果超时或生命值归零，则挑战失败。

## 1.2 保留的基础系统

以下机制全部沿用：

- WASD 自由移动。
- 最近三秒轨迹录制。
- Space 沿历史路径高速倒退。
- 倒带期间自身无敌。
- 倒带路径逐段攻击。
- 轨迹自交产生重影节点。
- 重影节点数量不设上限。
- 倒带经过交点时触发范围冲击波。
- 原有攻击冷却和玩家受伤无敌时间。

第二幕不新增玩家操作按键。

## 1.3 新增核心系统

本次版本增加：

1. 完整行动录像记录器 RunRecorder。
2. 录像数据结构 RunRecording。
3. 录像回放控制器 ReplayGhostController。
4. 幽灵攻击回放系统 ReplayAttackController。
5. 幽灵生命及受伤系统 GhostBossHealth。
6. 第二幕流程管理器 GhostDuelManager。
7. 录像回放提示及过场视觉效果。

# 二、完整游戏流程

## 2.1 第一幕结束条件

当第一幕生存计时达到 90 秒时：

1. 停止普通敌人生成。
2. 完成当前帧的玩家运动和攻击事件结算。
3. 停止 RunRecorder 录制。
4. 将 90 秒的玩家记录固定为只读 RunRecording。
5. 停止第一幕战斗逻辑。
6. 执行录像带倒回演出。

若玩家在 90 秒前生命值归零，则按照现有规则失败，不进入第二幕。

## 2.2 倒带过场

过场建议持续约 1.5–2 秒。

表现顺序：

1. 画面冻结。
2. 显示 `END OF TAPE`。
3. 录像画面出现噪点和横向扫描线。
4. 玩家过往的运动轨迹以高速闪回方式显示。
5. 播放磁带高速倒转的声音。
6. 屏幕计时器由 `01:30` 快速回到 `00:00`。
7. 画面短暂变黑。
8. 竞技场恢复初始画面。

该过程仅为视觉演出。

**不需要真正将第一幕的整个世界逐帧逆向模拟。**

过场结束时，直接重置场景对象即可。

## 2.3 第二幕初始化

执行以下操作：

- 删除第一幕遗留的全部普通敌人。
- 删除全部爆裂敌人。
- 清空待处理的连锁爆炸队列。
- 清空玩家原有的三秒轨迹。
- 清除第一幕剩余的重影节点。
- 将玩家移动至竞技场初始位置。
- 玩家生命值恢复为 3。
- 玩家倒带冷却重置为可用状态。
- 创建过去的自己。
- 为过去的自己加载 RunRecording。
- 初始化 Boss 生命值为 2。
- 初始化第二幕剩余时间为 30 秒。

转场完成后，显示：

`DUPLICATE SUBJECT DETECTED`

`ERASE YOUR PAST`

随后开始计时。

# 三、完整行动录像系统

## 3.1 为什么需要独立录像系统

现有 TrailRecorder 只保存最近三秒的轨迹。

该系统服务于玩家的即时倒带技能，不适合保存完整 90 秒的历史行动。

因此新增 RunRecorder。

两套录制系统具有不同职责。

| 系统 | TrailRecorder | RunRecorder |
|---|---|---|
| 保存时长 | 最近 3 秒 | 完整 90 秒 |
| 用途 | 当前玩家倒带 | 第二幕重演上一局 |
| 是否删除旧数据 | 是 | 否 |
| 倒带期间是否继续记录 | 否 | 是 |
| 保存攻击事件 | 不负责完整录像 | 是 |
| 第二幕是否重放 | 不重放 | 重放 |

RunRecorder 只在第一幕工作。

进入第二幕后不再向第一幕的录像追加数据。

## 3.2 位置录制

建议每 0.02 秒记录一次玩家实际状态。

采样率为 50 Hz。

完整 90 秒约产生 4500 条记录。

单条记录包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| Time | float | 第一幕经过时间 |
| Position | Vector2 | 玩家实际世界坐标 |
| IsRewinding | bool | 玩家是否处于倒带状态 |

示例 C# 数据结构：

```csharp
[System.Serializable]
public struct ReplayFrame
{
    public float time;
    public Vector2 position;
    public bool isRewinding;
}
```

录制时必须注意：

**玩家发动倒带期间，RunRecorder 仍然需要继续记录。**

因为第二幕必须重现过去的自己高速倒退时的实际运动。

不能只保存 WASD 输入，再尝试重新模拟历史操作。

## 3.3 攻击事件录制

仅保存角色位置还不够。

过去的自己在倒带时，需要重现此前真正扫过的攻击路径。

因此必须记录轨迹攻击事件。

```csharp
[System.Serializable]
public struct ReplayAttackSegment
{
    public float time;
    public Vector2 start;
    public Vector2 end;
    public float radius;
    public int actionId;
}
```

字段含义：

- time：该攻击线段实际生效的时间。
- start：攻击线段起点。
- end：攻击线段终点。
- radius：攻击判定半径。
- actionId：该次倒带攻击的唯一编号。

每次玩家在第一幕发动倒带时，分配新的 actionId。

倒带过程中，每个实际执行伤害判定的轨迹段，都写入一条 ReplayAttackSegment。

**必须记录所有攻击线段，而不是只记录曾经成功击中敌人的线段。**

因为原本没有击中敌人的斩击，在第二幕中仍然有可能击中当前玩家。

## 3.4 重影节点事件录制

由于 v0.2.1 已经取消重影节点数量上限，因此不能使用固定长度为 2 的数组保存节点爆炸。

使用动态列表记录所有实际触发的节点事件。

```csharp
[System.Serializable]
public struct ReplayNodeBurst
{
    public float time;
    public Vector2 position;
    public float radius;
    public int actionId;
}
```

每次第一幕中的重影节点真正爆炸时，保存一条事件记录。

第二幕不重新计算过去自己的轨迹交叉。

而是直接读取录制的节点爆炸事件。

这样可以保证：

- 第一幕触发多少次节点爆炸，录像中就保存多少次。
- 不受第二幕录制精度差异影响。
- 不会因为交叉检测重新执行而产生不同结果。
- 每个事件的爆炸位置、时间和范围都与第一幕一致。

第一幕由爆裂敌人产生的额外连锁爆炸，暂不作为第二幕的独立攻击事件回放。

第二幕只重演玩家自身的倒带斩击与重影节点爆炸。

## 3.5 录像数据集合

建议统一封装：

```csharp
public class RunRecording
{
    public List<ReplayFrame> frames = new();
    public List<ReplayAttackSegment> attacks = new();
    public List<ReplayNodeBurst> nodeBursts = new();
}
```

录制结束后，该对象视为只读数据。

第二幕使用它进行查询，不修改原始内容。

Boss 战失败后可以直接使用同一份录像重新挑战。

## 3.6 统一时间来源

所有 ReplayFrame、ReplayAttackSegment 和 ReplayNodeBurst 必须使用同一套第一幕游戏时钟。

禁止位置记录使用 Time.time，而攻击事件单独使用其他时间基准。

推荐由 GameManager 提供统一的 ActElapsedTime。

RunRecorder 在第一幕中使用该时间作为所有事件的时间戳。

位置录制应在角色当帧运动完成后进行。

攻击事件则在对应伤害轨迹段实际生效时记录。

# 四、第二幕录像播放规则

## 4.1 录像播放形式

第一幕长达 90 秒，而第二幕只有 30 秒。

不建议把全部录像以三倍速度播放。

三倍播放会让旧自己的移动速度和倒带斩击速度都明显增加，既难以预测，也可能造成不公平的命中。

因此采用**三段式录像剪辑回放**。

| 第二幕时间 | 使用的第一幕录像 |
|---|---|
| 0–10 秒 | 第一幕 0–10 秒 |
| 10–20 秒 | 第一幕 40–50 秒 |
| 20–30 秒 | 第一幕 80–90 秒 |

每段录像都以原始速度播放。

因此，过去的自己不会因为第二幕时长缩短而获得额外移动速度。

## 4.2 录像时间映射

定义：

- DuelTime：第二幕战斗时间，范围 0–30 秒。
- ReplayTime：当前读取的第一幕录像时间。

映射规则：

```text
0 ≤ DuelTime < 10:
    ReplayTime = DuelTime

10 ≤ DuelTime < 20:
    ReplayTime = DuelTime + 30

20 ≤ DuelTime ≤ 30:
    ReplayTime = DuelTime + 60
```

例如：

第二幕第 5 秒对应第一幕第 5 秒。

第二幕第 15 秒对应第一幕第 45 秒。

第二幕第 25 秒对应第一幕第 85 秒。

这保证开头、中段和结尾的玩家行为都可以参与第二幕。

## 4.3 位置回放

ReplayGhostController 根据 ReplayTime 查找相邻两条 ReplayFrame。

通过线性插值获得幽灵角色的位置。

正常连续播放时使用插值，以避免采样点之间产生明显跳动。

但在 10 秒和 20 秒的录像剪辑点，不允许跨片段插值。

否则旧自己可能从第一幕第 10 秒的位置，直接沿直线快速移动到第 40 秒的位置。

这种行为并不存在于真实录像中。

## 4.4 录像跳切

第二幕第 10 秒和第 20 秒发生录像跳切。

流程：

1. 暂停第二幕战斗时间。
2. 显示短暂的画面噪点。
3. 清除上一片段尚未结束的幽灵攻击预警与判定。
4. 将过去的自己直接移动至下一片段起点。
5. 更新过去自己的历史轨迹视觉。
6. 播放 `TAPE SKIP` 音效。
7. 恢复战斗。

建议每次跳切使用约 0.4 秒的短过场。

过场不消耗 30 秒战斗时间。

为防止玩家在瞬移后立即受到不可预判的攻击，新片段开始后的前 0.5 秒可以禁止过去自己的攻击造成伤害，但仍正常播放移动和攻击动画。

# 五、过去的自己：Boss 行为

## 5.1 基础属性

| 属性 | 初始值 |
|---|---:|
| 生命值 | 2 |
| 可被攻击半径 | 0.85 Unity 单位 |
| 受伤后无敌 | 0.7 秒 |
| 移动速度 | 由录像决定 |
| 倒带速度 | 由录像决定 |
| AI 寻路 | 无 |
| 主动追踪玩家 | 无 |
| 普通接触伤害 | 无 |
| 是否可以被倒带冻结 | 是 |

过去的自己在第二幕中仅有两类行为：

1. 按照录像移动。
2. 按照录像发动攻击。

它不根据当前玩家位置调整路径。

## 5.2 角色移动

正常情况下，过去的自己按照 ReplayFrame 的 Position 移动。

如果录制状态显示该时刻正在倒带，则显示对应的倒带动画和视觉效果。

录像中的位置已经包含原本倒带期间的高速移动，因此不需要再调用 RewindController 重新计算过去自己的倒带路径。

## 5.3 过去自己的倒带攻击

当 ReplayTime 到达一条 ReplayAttackSegment 的记录时间时：

1. 取得攻击起点和终点。
2. 显示红色或紫红色攻击轨迹。
3. 判断当前玩家是否处于攻击范围。
4. 如果命中，则对当前玩家造成伤害。
5. 继续读取后续攻击线段。

攻击判定仍然采用线段与目标圆形碰撞的方法。

不能只检查轨迹段的起点或终点。

幽灵的攻击半径沿用第一幕的基础轨迹攻击半径，初始为 0.55 单位。

## 5.4 攻击预警

录像攻击必须可预测。

在过去的自己发动倒带前约 0.5 秒，提前显示对应的攻击路径。

推荐效果：

- 即将执行的倒带路径显示为闪烁的红色虚线。
- 旧自己角色外圈开始闪烁。
- 播放短促的录像故障提示音。
- 真正进入攻击阶段后，虚线变成实体红色攻击轨迹。

由于全部攻击路径已经保存在 RunRecording 中，可以提前查询未来 0.5 秒即将出现的攻击事件。

预警期间不会造成伤害。

如果攻击发生在录像片段开头，导致无法提供完整预警时间，应优先保证安全提示，必要时跳过该次攻击的伤害判定。

## 5.5 过去自己的重影节点爆炸

当 ReplayTime 到达 ReplayNodeBurst 的记录时间时：

1. 在记录位置显示紫红色重影节点。
2. 节点释放圆形冲击波。
3. 查询玩家是否处于爆炸半径内。
4. 如果玩家可受伤，则造成 1 点伤害。
5. 播放冲击波扩散动画。

节点爆炸前 0.5 秒显示预警圆圈，明确告知爆炸范围。

由于第一幕可能记录多个节点事件，因此第二幕允许连续触发多个过去的重影节点爆炸。

所有事件按录制时间顺序执行。

同一时间范围内的多个攻击，由玩家受伤无敌机制保护，避免瞬间损失全部生命值。

# 六、当前玩家的战斗规则

## 6.1 操作与能力

当前玩家继续使用：

- WASD：移动。
- Space：倒带攻击。

倒带记录窗口仍为 3 秒。

倒带攻击方式与第一幕完全一致。

当前玩家仍然可以通过自交轨迹生成无限数量的有效重影节点。

## 6.2 命中 Boss

Boss 可以受到以下攻击：

1. 玩家倒带轨迹的直接斩击。
2. 玩家重影节点爆炸产生的冲击波。

普通移动不能伤害 Boss。

每次玩家发动倒带，分配一个唯一的 CurrentRewindActionId。

**一次完整倒带最多对 Boss 造成 1 点伤害。**

无论该次倒带中：

- 直接命中多少次；
- 经过多少个重影节点；
- 多少个冲击波同时覆盖 Boss；

Boss 都最多损失 1 HP。

这条规则用于保证第二幕必须完成至少两次成功攻击。

不限制重影节点的生成和爆炸数量，只限制它们对 Boss 的单次倒带累计伤害。

## 6.3 倒带期间的录像冻结

当当前玩家发动倒带时：

- 过去的自己停止播放录像。
- 过去自己的位置保持不变。
- 过去自己的攻击事件暂时停止推进。
- 第二幕 30 秒战斗计时暂停。
- 当前玩家仍按照已有轨迹完成倒带攻击。

当玩家倒带结束后：

- 过去的自己恢复录像播放。
- 30 秒计时继续。
- 原本尚未执行的幽灵攻击继续等待对应时间。

这样可以保持与第一幕「倒带期间敌人被冻结」的规则一致。

也能避免当前玩家无法控制角色时，过去自己的斩击仍然继续攻击。

**第二幕 30 秒指的是正常战斗时间，不包括玩家短暂倒带和录像跳切所暂停的时间。**

## 6.4 玩家受伤

当前玩家初始为 3 HP。

以下情况可能造成伤害：

- 被过去自己的倒带轨迹命中。
- 被过去自己的重影节点冲击波命中。

以下情况不会造成伤害：

- 与过去自己的普通角色碰撞。
- 接触过去自己的非攻击状态历史轨迹。
- 当前玩家正在倒带且处于无敌状态。

受到伤害后，沿用 0.75 秒无敌时间。

## 6.5 命中反馈

Boss 受伤时：

- 旧自己短暂闪白。
- 播放磁带撕裂音效。
- 显示 `PARADOX HIT`。
- Boss HP 减少 1。
- 屏幕产生轻微错位或色差。

第二次有效命中后，Boss 进入死亡状态。

不继续播放剩余录像。

# 七、录像回放与伤害结算

## 7.1 录像事件查询

第二幕每帧维护：

- PreviousReplayTime。
- CurrentReplayTime。

系统应当查询该时间区间内发生的所有事件。

包括：

- 攻击线段事件。
- 重影节点爆炸事件。

事件按照录制时间升序处理。

不能只检查当前时间是否恰好等于事件时间。

因为游戏帧率变化可能导致 ReplayTime 直接跨越某个事件时间。

## 7.2 攻击数据不重新模拟

过去自己的攻击只根据 RunRecording 中的原始事件执行。

禁止使用过去角色当前位置重新运行第一幕的轨迹检测算法。

原因：

- 录像插值可能造成位置误差。
- 倒带过程中时间暂停方式可能与第一幕不同。
- 重影节点数量无限，重新检测可能得到不同的交点结果。
- 第二幕的敌人分布已经改变。

因此，第二幕遵循：

**录像决定过去的自己做了什么；当前世界只负责判断这些已记录的行为是否命中了现在的玩家。**

## 7.3 攻击去重

当前玩家和过去的自己都需要统一的生命状态管理。

过去的自己：

- 同一次玩家倒带最多受到 1 点伤害。
- 死亡只发生一次。
- 已死亡时不再接受伤害。
- 死亡后停止录像及攻击。

当前玩家：

- 受伤无敌期间忽略新的伤害。
- 同一次幽灵攻击不得因连续多帧重叠而重复扣血。
- 当前玩家处于倒带无敌状态时忽略幽灵攻击。

# 十、第二幕状态执行流程

## 10.1 第一幕到第二幕

```text
ACT I — SURVIVAL
        |
        | 90 秒结束
        v
停止完整录像
        |
        v
生成只读 RunRecording
        |
        v
END OF TAPE 过场
        |
        v
清空第一幕敌人、轨迹及爆炸
        |
        v
初始化当前玩家与过去的自己
        |
        v
ACT II — PLAYBACK
```

## 10.2 第二幕每帧逻辑

在 Fighting 状态下：

1. 检查当前玩家是否正在倒带。
2. 如果正在倒带，暂停录像与第二幕战斗时钟。
3. 如果正常战斗，推进 DuelTime。
4. 根据 DuelTime 计算 ReplayTime。
5. 判断是否到达录像跳切点。
6. ReplayGhostController 更新过去自己的位置。
7. ReplayAttackController 查询即将发生的攻击，显示预警。
8. 处理该时间区间内所有已录制的攻击事件。
9. 检查当前玩家受伤。
10. 处理当前玩家攻击过去自己的伤害。
11. 更新 Boss HP 和 HUD。
12. 检查 Boss 死亡、玩家死亡或挑战超时。

当某一帧同时发生 Boss 死亡和计时归零时，应先完成该帧的伤害结算。

若 Boss HP 已归零，则判定玩家胜利；否则按照超时失败处理。

## 10.3 Boss 死亡

当 Boss HP 归零时：

1. 将 Boss 标记为 Dead。
2. 停止录像播放。
3. 关闭幽灵攻击伤害判定。
4. 清除所有尚未触发的危险预警。
5. 停止 30 秒倒计时。
6. 播放幽灵分解动画。
7. 显示 `PAST RECORD ERASED`。
8. 向 GameManager 发送第二幕通关事件。
9. 进入后续剧情或第三幕。

本文件不定义第三幕的具体玩法。

## 10.4 第二幕失败

发生以下任一情况时失败：

- 30 秒战斗时间耗尽，Boss 仍然存活。
- 当前玩家生命值归零。

失败后显示：

`TEMPORAL CONFLICT UNRESOLVED`

`CURRENT INSTANCE REJECTED`

提供两个选项：

**Retry Duel**

直接重新挑战第二幕，继续使用已保存的 RunRecording。

**New Recording**

从第一幕重新开始，创建新的 90 秒录像。

重试第二幕时，不需要重新执行第一幕，也不需要从磁盘读取或保存录像文件。

RunRecording 在当前游戏会话内保留即可。

# 十二、场景与视觉设计

## 12.1 幽灵外观

过去的自己复用玩家原有 Sprite。

建议改变以下参数：

- 主色调改为紫红色。
- 透明度约为 80%。
- 增加轻微故障抖动。
- 正常历史轨迹显示为暗紫色。
- 倒带攻击轨迹显示为红色。

- 画面短暂闪烁。

- 显示短暂的旧式录像机噪声。

不要使用长时间黑屏，避免打断战斗节奏。

## 12.3 攻击可读性

建议视觉层级：

1. 玩家角色。
2. 过去的自己。

4. 当前玩家的可用轨迹。
5. 普通历史轨迹。

在第二幕中，应适当降低 CRT 背景噪点的强度，避免红色危险轨迹被视觉效果掩盖。

# 十五、主要风险及处理方案

## 15.1 玩家可能很难击中完全按照录像移动的 Boss

过去的自己并不主动追踪玩家，因此无法保证它自然进入玩家的攻击路径。

处理方式：

- 显示旧自己未来约 1 秒的移动路线。
- 适当增大 Boss 受击半径。
- 保持当前玩家倒带时 Boss 冻结。
- 允许重影节点范围爆炸伤害 Boss。

如果实际测试仍然很难命中，应优先降低 Boss HP 或延长第二幕时限，而不是增加新操作。

## 15.2 第一幕录像可能很少包含倒带攻击

如果玩家在第一幕几乎没有发动倒带，过去的自己在第二幕也就没有多少攻击手段。

这是允许的。

过去的自己应当忠实地反映第一幕的玩家行为。

不能凭空为它增加未曾录制过的倒带技能。

## 15.3 过去的自己可能过于危险

第一幕中玩家可能频繁使用倒带，并形成大量重影节点。

第二幕重放时可能产生密集的危险区域。

处理方式：

- 所有攻击提前预警。
- 保留玩家受伤无敌机制。
- 录像跳切后提供短暂无伤害保护。
- 玩家自己的倒带可以暂停幽灵时间。

不要直接删除已录制的攻击事件来降低难度。

## 15.4 录像播放与战斗时间可能不同步

这一问题可能出现在：

- 当前玩家发动倒带。
- 录像跳切。
- 画面暂停。
- 游戏出现性能波动。

处理方式：

第二幕使用独立的 DuelClock 管理正常战斗时间。

所有幽灵移动和攻击均由 DuelClock 映射得到的 ReplayTime 驱动。

暂停时统一停止 DuelClock 推进，而不是分别暂停角色和攻击计时器。

## 15.5 第二幕失败后反复重玩第一幕会降低体验

因此必须保留 Retry Duel。

玩家挑战失败后可以立即再次尝试与同一个过去自己战斗。

只有选择 New Recording 时才重新录制第一幕。

# 十六、第二幕完成标准

v0.3 完成后应满足：

1. 第一幕完整记录 90 秒玩家行为。
2. 保存真实运动、倒带攻击和全部重影节点爆炸事件。
3. 第一幕结束后正确进入第二幕。
4. 过去的自己严格按照上一局录像移动。
5. 过去的自己能够重演上一局真实发生的倒带攻击。
6. 过去的重影节点能够按录像时间产生敌对冲击波。
7. 当前玩家可以用原有倒带机制攻击过去的自己。
8. 当前玩家的无限重影节点机制在第二幕正常工作。
9. 一次当前玩家倒带对 Boss 最多造成 1 点伤害。
10. Boss 在两次有效攻击后死亡。
11. 第二幕具有独立的 30 秒战斗计时。
12. 两次录像跳切不会造成位置、攻击或时间异常。
13. 玩家胜利后能够进入后续剧情。
14. 玩家失败后可以直接重新挑战同一段录像。
15. 不破坏第一幕原有的生存、倒带及连锁爆炸系统。

# 十七、叙事与玩法的统一

第二幕不需要通过大量文本解释故事。

玩家只需要经历三个事实：

首先，第一幕的所有行动都被记录了下来。

其次，录像被重新播放时，过去的自己真实地出现在眼前。

最后，自己曾经用来保护自己的倒带攻击，如今变成了来自过去的威胁。

这让第二幕既是剧情反转，也是对第一幕玩法的重新解释。

**ACT I：USE YOUR PAST TO SURVIVE.**

**ACT II：USE YOUR PAST TO DESTROY YOUR PAST.**

玩家必须利用刚刚学会的时间能力，面对由自己亲手创造的敌人。

**第二幕的设计核心：你击败的不是拥有相同能力的 AI，而是已经发生过、无法改变的自己。**
